# Commit Message Guidelines

## 1. Schema Template

```text
<type>(<scope>)<!>: <subject>

- <body: what/why>

BREAKING CHANGE: <description>
```

## 2. Header Specification (MUST)

- **Validation Regex**:
  `^(build|ci|docs|feat|fix|perf|refactor|style|test|chore)(\([a-z0-9-]+\))?(!)?: [^\s].{0,29}$`

| Component | Level | Constraints |
| :--- | :--- | :--- |
| `type` | **MUST** | `build` \| `ci` \| `docs` \| `feat` \| `fix` \| `perf` \| `refactor` \| `style` \| `test` \| `chore` |
| `scope` | **SHOULD** | `[a-z0-9-]+` (kebab-case, e.g., `api`, `auth`, `db`, `ui`). Omit only when change scope is self-evident. |
| `!` | **MUST** | Append immediately after `type` or `(scope)` if and only if breaking change is introduced. |
| `subject` | **MUST** | Japanese text. Length $\le$ 30 chars. No trailing punctuation (`。`, `.`). Use direct verb endings (e.g., `〜を追加`, `〜を修正`, `〜を更新`, `〜を削除`). |

### Type Definitions

- `build`: Build system or external dependencies
- `ci`: CI configuration / pipelines
- `docs`: Documentation only
- `feat`: New feature
- `fix`: Bug fix
- `perf`: Performance improvement
- `refactor`: Structural refactoring without behavior change
- `style`: Formatting / whitespace only (no logic change)
- `test`: Test code additions or modifications
- `chore`: Auxiliary tasks / maintenance

## 3. Body Specification (CONDITIONAL)

- **Condition**: **MUST** omit if header is sufficient. Provide only when rationale (Why) or non-obvious context (What) is required.
- **Delimiter**: **MUST** leave exactly 1 blank line after header.
- **Format**: **MUST** be Japanese bulleted list (`-`). Max 72 chars per line.
- **Content**: **SHOULD** cover What and Why.

## 4. Breaking Changes (CONDITIONAL)

- **Condition**: **MUST** apply only when introducing breaking changes.
- **Header**: **MUST** append `!` to header (`type!` or `type(scope)!`).
- **Footer**: **MUST** append footer separated by a blank line (`BREAKING CHANGE: <migration details in Japanese>`).

## 5. Canonical Examples

### Header Only

```text
feat(auth): Googleログイン機能を追加
```

### With Context Body

```text
fix(ui): 送信ボタンの連打を防止

- 送信直後にボタンを非活性化する処理を追加
- 重複送信によるAPIエラーを抑制するため
```

### Breaking Change

```text
feat(db)!: カラム名を変更

- `node.type` を `node.typeId` にリネーム

BREAKING CHANGE: 既存データのマイグレーションが必要
```
